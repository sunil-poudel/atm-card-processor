# 09. DevOps, Quality and Operations

## 1. Environments and profiles

| Profile | Purpose | Notes |
|---------|---------|-------|
| `dev` | Local development | Postgres from `deploy/docker-compose.dev.yml`; fixed non-secret dev keys in `application-dev.yml`; Swagger UI on; `app.cards.expose-pan-on-issue=true`; `demo` profile may be added for sample data |
| `test` | Automated tests | Testcontainers PostgreSQL; fixed test keys in test resources; fixed/adjustable `Clock` bean in tests |
| `prod` | Compose "production-like" and any real deployment | No default secrets; validation fails on missing; JSON logs; Swagger off; `expose-pan-on-issue=false` unless explicitly set; actuator restricted |

The Compose stack runs profile `prod` plus a demo toggle (`SPRING_PROFILES_ACTIVE=prod,demo` only when `DEMO_DATA=true` in `.env`) with env-provided secrets generated by `scripts/gen-secrets.sh` or copied from `.env.example` for local demos (the example values are **obviously fake**, 32+ bytes, and clearly marked "development only").

## 3. Dockerfiles

### 3.1 Backend (`backend/Dockerfile`)
- Stage 1 `build`: `eclipse-temurin:21-jdk` (or a Maven image with JDK 21), copy `pom.xml`, `mvnw`, `.mvn`, run `./mvnw -B -q dependency:go-offline`, then copy `src` and `./mvnw -B -DskipTests package` (tests run in CI, not in the image build) and extract Spring Boot **layers** (`java -Djarmode=tools -jar app.jar extract --layers --destination extracted` or the `layertools` equivalent for the installed version; verify).
- Stage 2 runtime: `eclipse-temurin:21-jre`, create a non-root user (`app`, uid 10001), copy layers in cache-friendly order (dependencies, spring-boot-loader, snapshot-dependencies, application), `EXPOSE 8080`, `HEALTHCHECK` using the readiness endpoint (use `wget -qO-` if present or a tiny `java` based check; ensure the tool exists in the image), `ENTRYPOINT ["java","-XX:MaxRAMPercentage=75","-jar","app.jar"]` (adapt to the layered launch command).
- `.dockerignore`: `target`, `.git`, `*.md`, IDE files.
- JVM: container-aware flags, `-XX:+ExitOnOutOfMemoryError`, graceful shutdown enabled (`server.shutdown=graceful`, `spring.lifecycle.timeout-per-shutdown-phase=20s`).

### 3.2 Frontend (`frontend/Dockerfile`)
- Stage 1: `node:<lts>-alpine`, `npm ci`, `npm run build -- --configuration production`.
- Stage 2: `nginxinc/nginx-unprivileged:stable-alpine`, copy `dist/<app>/browser` to `/usr/share/nginx/html`, copy `deploy/nginx.conf`, listen on 8081, non-root.
- `.dockerignore`: `node_modules`, `dist`, `.angular`, `e2e/test-results`.

### 3.3 nginx (`deploy/nginx.conf`)
- `location /api/ { proxy_pass http://backend:8080; proxy_set_header X-Request-Id $request_id (only if client did not send one: simplest is to leave it to the backend); X-Forwarded-For/Proto/Host; proxy_read_timeout 30s; }`
- `location / { try_files $uri $uri/ /index.html; }` with `Cache-Control: no-store` on `index.html` and long-lived immutable caching on hashed assets.
- Security headers from `06` §6; gzip on; `server_tokens off`; client_max_body_size 1m.
- Backend must trust forwarded headers only from the proxy: `server.forward-headers-strategy=framework` (or `native`) in the `prod` profile so client IPs in audit events are correct.

## 4. Docker Compose

`deploy/docker-compose.yml`:
- `postgres`: image `postgres:17-alpine`, env from `.env`, named volume `pgdata`, healthcheck `pg_isready -U $POSTGRES_USER -d $POSTGRES_DB` (interval 5 s, retries 10), no published port by default (profile `dev-ports` optional) .
- `backend`: build `../backend`, `depends_on: postgres: condition: service_healthy`, env from `.env`, healthcheck on readiness, `restart: unless-stopped`, port `8080:8080`.
- `frontend`: build `../frontend`, `depends_on: backend: condition: service_healthy`, port `8081:8081`.
- `read_only: true` + `tmpfs` where it works; `cap_drop: [ALL]`; `security_opt: [no-new-privileges:true]` (apply where the image supports it; verify the stack still starts).
- Resource-friendly defaults; a single bridge network; no `latest` tags.

`deploy/docker-compose.dev.yml`: Postgres only, port 5432 published, used with `./mvnw spring-boot:run -Dspring-boot.run.profiles=dev`.

`./scripts` documented commands: `docker compose -f deploy/docker-compose.yml --env-file deploy/.env up --build -d` and `... down -v`.

## 5. Scripts

| Script | Behaviour |
|--------|-----------|
| `scripts/verify-all.sh` | `set -euo pipefail`. Steps with clear banners: (1) backend `./mvnw -f backend -B verify`; (2) export/check OpenAPI is unchanged (`git diff --exit-code docs/openapi.json` after the backend build); (3) frontend `npm ci`, `npm run api:types` + `git diff --exit-code`, `lint`, `format:check`, `test`, `build`; (4) Compose up with a temporary `.env` copied from `.env.example`, wait for health, run `scripts/smoke-test.sh`, run Playwright e2e, always `docker compose down -v` in a `trap`. Exits non-zero on the first failure. Supports `--skip-e2e` and `--skip-docker` flags for quick runs, but the **final** verification runs with no flags. |
| `scripts/smoke-test.sh` | Uses `curl` + `jq` (check availability; fall back to a Node script if `jq` is missing): wait for `/actuator/health/readiness`; login as bootstrap admin; issue a card with initial balance; activate; authorize (expect `APPROVED 00`); replay same key (expect identical body and replay header); decline over limit (expect `61`); read transaction; fetch report; print a green summary. |
| `scripts/export-openapi.sh` | Starts the app (or uses the integration test with `-Dopenapi.update=true`) to refresh `docs/openapi.json` deterministically (sorted keys, no volatile fields). |
| `scripts/gen-secrets.sh` (optional) | Writes `deploy/.env` with fresh random values using `openssl`. |
| `scripts/load-test.js` (COULD) | k6 script for `POST /authorize` at 50 rps; documents results, not a gate. |

All scripts are POSIX/bash-compatible, executable (`chmod +x`), with usage comments, and tested by running them.

## 6. CI (GitHub Actions, `.github/workflows/ci.yml`)

Triggers: `push` and `pull_request` on `main`. Concurrency group cancels superseded runs. Jobs:

1. **backend**: `actions/setup-java` (Temurin 21, Maven cache), `./mvnw -f backend -B verify` (Testcontainers works on the GitHub runner Docker), upload JaCoCo report and test reports as artifacts.
2. **frontend**: `actions/setup-node` (LTS, npm cache), `npm ci`, `api:types` + `git diff --exit-code`, `lint`, `format:check`, `test`, `build`.
3. **e2e**: needs both; builds the Compose stack, runs smoke test and Playwright, uploads the Playwright report and traces on failure.
4. **docker-build** (optional but nice): builds both images with Buildx cache, no push.
5. **security** (SHOULD): `npm audit --audit-level=high` (non-blocking report), a secret-pattern grep.

Pin third-party actions to a major version tag (or SHA); minimal `permissions: contents: read`; set timeouts per job. A status badge for the workflow goes in `README.md`. Because the agent cannot run GitHub-hosted CI, it validates the workflow syntax locally (for example with `actionlint` if installable, else carefully by review) and states in `FINAL_REPORT.md` that CI was not executed remotely.

## 7. Observability

- **Health**: liveness and readiness groups enabled; readiness includes the DB. `management.endpoint.health.probes.enabled=true`. Details hidden from anonymous callers.
- **Metrics** (Micrometer, exposed as Prometheus on the management port 9090 or ADMIN-only on the main port): `minicard.authorizations` counter tagged `status`, `responseCode`, `declineReason`; `minicard.authorization.duration` timer (publish percentiles 0.5/0.95/0.99); `minicard.fraud.flagged` counter; `minicard.disputes.opened` and `minicard.disputes.auto_closed` counters; `minicard.ledger.entries` counter tagged `type`. Metrics must not contain PANs or ids as tags (cardinality).
- **Logs**: see `06` §8. Request id in every line. Log sampling is not needed.
- **Tracing**: out of scope.
- **Info endpoint**: build info (version, commit when available) through the Boot build-info goal.

## 8. Database operations

- Flyway runs at startup (`spring.flyway.validate-on-migrate=true`); migrations immutable; baseline not needed (greenfield).
- A test migrates an empty Testcontainers database from V1 to latest and runs JPA schema validation (proves entities match migrations).
- Connection pool: HikariCP defaults with explicit `maximum-pool-size=10`, `connection-timeout=5s`, and a statement/lock timeout of 3 s for lock waits (see `07` §4).
- Backup/restore: documented as a README note (`pg_dump`), not automated.

## 9. README requirements (`README.md` at the repo root)

Must contain, in this order: title + one-sentence pitch; CI badge; screenshots (from `docs/screenshots/`); features; architecture diagram (mermaid) and short explanation; tech stack with versions; **Quick start** (prerequisites, `cp deploy/.env.example deploy/.env`, `docker compose ... up --build`, URLs, default admin from `.env`, how to log in and try the simulator); local development (backend and frontend commands); running tests and the full verification; API overview with link to `docs/openapi.json` and Swagger URL; configuration table (condensed from §2); security notes; **Design decisions** (links to ADRs); **Limitations** (the table in `01` §5); project structure; contributing/commit conventions; license. No marketing fluff, no emojis, no claims that are not verified.

Other required docs: `docs/adr/*.md` (ADR list in `02` §5; add more as decisions arise), `docs/CODE-TOUR.md` (where to start reading, a guided path through authorize -> ledger -> fraud -> dispute, with file paths), `docs/INTERVIEW-QA.md` (at least 25 questions and honest answers about the design; see `12` for the list of topics), `docs/FINAL_REPORT.md` (what was built, how it was verified with command outputs summarized, coverage numbers, known limitations, things the owner must check manually).

## 10. Repository hygiene

- `.gitignore` for Java, Node, IDEs, OS files, `.env`, `deploy/.env`.
- `.editorconfig` (UTF-8, LF, 2 spaces for web/yaml/json, 4 for Java if google-java-format is not enforced; with google-java-format use 2 for Java).
- `.gitattributes` (`* text=auto eol=lf`, `*.sh text eol=lf`, binary types).
- Conventional Commits (`feat:`, `fix:`, `test:`, `docs:`, `chore:`, `refactor:`, `ci:`, `build:`) with scope where useful (`feat(authorization): ...`), imperative subject under 72 chars, body explains why when non-obvious.
- No generated artifacts committed (except `docs/openapi.json`, `frontend/src/app/core/api/schema.d.ts`, lock files, screenshots).
- License MIT with the owner's name placeholder resolved from `git config user.name` or "ATM Card Processor contributors".
